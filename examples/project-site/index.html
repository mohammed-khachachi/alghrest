تحديث مستند README

ALGHREST منصة تداول ذاتية متعددة الوكلاء مبنية حول Kafka والمخاطر والمراقبة.

المشروع يعمل كبنية event-driven من 7 طبقات و37 خدمة تقريبا: وكلاء ذكاء واستراتيجيات وتنفيذ يتواصلون عبر Kafka، يشاركون الحالة عبر Redis، ويحفظون بيانات الزمن الحقيقي في TimescaleDB.

عرض للمستثمر

ALGHREST ليس روبوت تداول بسيط، بل منصة وكلاء قابلة للتوسع ومبنية حول المخاطر.

قابلية الاستثمار

النظام مقسم إلى خدمات ووكلاء، ما يسمح بالتوسع وإضافة قدرات جديدة دون إعادة بناء كل شيء.

مخاطر واضحة

كل قرار تداول يمر عبر طبقة مخاطر وحدود رأس مال قبل الوصول إلى التنفيذ.

قابلية العرض

يمكن تحويل كل heartbeat وقرار ورسالة Kafka إلى لوحة مراقبة مقنعة للمستثمر.

ماذا يمكنه أن يفعل؟

النظام مصمم ليغطي دورة التداول كاملة من جمع البيانات إلى تنفيذ الأوامر.

01

تحليل السوق

يجمع الأسعار، الأخبار، المعنويات، المؤشرات الاقتصادية، بيانات on-chain، والعوامل الجيوسياسية.

02

إنتاج استراتيجيات

يدعم استراتيجيات trend، mean reversion، momentum، statistical arbitrage، breakout، macro rotation، و ML predictor.

03

إدارة المخاطر

يطبق حدود المركز، حد 1% للمخاطرة في الصفقة، إيقاف بعد خسائر متتالية، وقاطع طوارئ عند ارتفاع الخطر.

04

تنفيذ الأوامر

يمرر المقترحات إلى الموافقة، ثم توجيه الأمر، تحسين الرسوم، تقليل الانزلاق، ثم التنفيذ وتأكيد الصفقات.

05

مراقبة مباشرة

Dashboard يعرض حالة الوكلاء، الأرباح والخسائر، التنبيهات، صحة النظام، وتحديثات WebSocket.

!

DeFi غير جاهز للإنتاج

وكلاء DeFi الحاليون هياكل أولية فقط. لا يجب تشغيلهم بأموال حقيقية قبل دمج البروتوكولات واختبارها.

الوكلاء أثناء العمل

لوحة حية توضح كيف تتحرك الوكلاء داخل النظام.

هذا العرض يحاكي التشغيل الحقيقي: كل وكيل يرسل heartbeat، يقرأ أو ينشر رسائل، ويتغير حمله حسب نوع المهمة. عند تشغيل النظام فعليا يمكن ربط هذه الخانة ببيانات API أو WebSocket.

مسار الصفقة

من فكرة الاستراتيجية إلى تنفيذ الصفقة.

1 Strategy → PROPOSALS_BUS

الاستراتيجية تولد مقترح تداول من Tier 4.

2 ProposalApprover

يفحص PositionLimitChecker ثم ينشر إلى PROPOSALS_APPROVED.

3 OrderRouter

يختار البورصة والخوارزمية ثم يرسل إلى ORDERS_PENDING.

4 Fee + Slippage

FeeOptimizer يضيف _optimised وSlippageMinimizer يقسم TWAP/VWAP بعلامة _child.

5 ExchangeExecutor

ينفذ الأمر وينشر ORDERS_EXECUTED وFILLS_CONFIRMED.

حدود الأمان

المشروع يحتوي على حواجز أمان يجب احترامها.

ابدأ ببيئة development أو paper_trading

النظام يرفض الأوامر الحقيقية إلا إذا تم ضبط ENVIRONMENT=live صراحة.

لا تشغل DeFi بأموال حقيقية

وكلاء yield farmer و dex arbitrageur و mev hunter و bridge strategist غير جاهزين للإنتاج.

احم المفاتيح السرية

ملف .env لا يجب رفعه إلى Git، ومفاتيح البورصات يجب أن تكون دون صلاحية سحب.

اختبر قبل live

الاستراتيجيات يجب أن تمر عبر backtesting و paper trading قبل أي تشغيل حقيقي.

لا تلين حدود المخاطر

حد المخاطرة 1% للصفقة، الإيقاف بعد 5 خسائر متتالية، drawdown أقصى 25%، والمحفظة الساخنة لا تتجاوز 5%.

بوابة backtesting إلزامية

أي استراتيجية Tier 4 تحتاج 5 سنوات بيانات، 50 صفقة سنويا، Sharpe وProfit Factor وMonte Carlo ضمن الحدود.
